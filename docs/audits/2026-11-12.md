# CVUnicorn site audit — 12 November 2026

Scope: marketing routes, desktop/mobile presentation, CV intake, generation brief, editing, checkout, renewal, private preview and publishing. The existing brand and Valerio portfolio were preserved.

## Findings and repairs

| Priority | Finding | Repair |
| --- | --- | --- |
| P1 | Selected style and module attachment text were not fully reflected in generation | Explicit style directions, source attachment text, language control and portrait requirements in the brief; billing email excluded |
| P1 | Regeneration could replace a live site before review | Separate private preview, authenticated publish action, generation/publish lease; failed generation preserves the published site |
| P1 | Paid editing and renewal did not reliably continue the original site | Authenticated draft editor, awaited saves, original-order renewal with idempotent extension and preserved site URL |
| P1 | Generated code shared the application origin | Opaque-origin CSP sandbox, blocked forms/network/frames, strict output checks and untrusted upload rejection |
| P1 | Unsafe production fallbacks and dependency advisories | Disabled simulated production payments, require production signing secret/blob storage, compatible dependency security updates |
| P2 | Uploaded CV extraction could not be reviewed easily | Editable extracted text and explicit language selection; PDF extraction regression uses a local source file only |
| P2 | White button labels overridden; missing page headings and keyboard affordances | Restored white labels, h1 headings, visible focus, keyboard file upload and mobile menu Escape handling |
| P2 | Tiny examples and expensive hero images | Larger two-column examples, truthful demo labels, WebP assets: 4,976,490 to 135,302 bytes (97.3% smaller) |
| P2 | Product copy promised features beyond the implemented flow | Accurate paid pass → private preview → publish flow, assisted domain setup, no claim of automatic dashboard email delivery |

## Verification

- TypeScript check and production build pass.
- Six automated API/core tests cover briefs, malformed intake/output, authenticated editing, private preview/publishing, failed regeneration, expiry, renewal idempotence, uploads, leases and document extraction.
- Browser suite covers twelve routes at 1440px and 390px, WCAG A/AA axe checks, horizontal overflow, JavaScript errors, a no-JavaScript homepage and the full local purchase/edit/preview/publish flow.
- Final browser result: all 24 route/viewport combinations returned successfully, with zero detected WCAG violations, horizontal overflow or uncaught page errors. The private preview rendered and could not read the parent's local storage.
- Model responses are mocked and checkout uses the local simulated provider. These tests do not represent a real provider charge or a sample of live model design quality.
- Dependency audit after compatible updates: zero reported vulnerabilities.
- One Impeccable detector pass: three existing decorative advisories (one side-tab and two grid backgrounds). Retained as incumbent demo design choices; no new decorative redesign introduced.

## Remaining boundaries

- Deployment verification: implementation commit `64230b0` is on GitHub `main`; Vercel reports a successful Production deployment in `valerioliynap-9144s-projects/cvunicorn`. The owner-authorized bindings for `cvunicorn.com`, `www.cvunicorn.com`, `*.cvunicorn.com`, `mayachen.cvunicorn.com`, `noahrivera.cvunicorn.com` and `ariokafor.cvunicorn.com` now show **Valid Configuration / Production**. Public checks confirm the new primary/www pages, the 37,884-byte WebP asset, all three case-study pages referencing their new WebP images, and HTTP 403 for unauthenticated editor/preview access. All six existing public sites returned HTTP 200. Per the owner's final instruction, **Valerio's explicit binding was not changed**; its original resume route remains accessible and contains Questant. An additional arbitrary unpublished-host probe timed out at the network layer, so wildcard application routing for a newly generated site has not been verified end to end. An unintended invalid domain entry created during UI operation was removed and its absence verified before proceeding.

- Live model output still needs an actual generation sample to assess its editorial/design quality. Prompt validation and deterministic fixtures cannot prove that every future generation looks good.
- Custom domain registration/setup remains assisted. Automatic dashboard-link email delivery remains unimplemented; the success page and saved local dashboard link are the available access paths.
- Wizard language support improved; the entire checkout/account/support experience is not fully translated.
- Existing published documents are preserved. New generation rules apply when a customer regenerates, not retroactively.
- Uploaded assets use shareable storage URLs. Do not describe those URLs as private storage.
- Automated accessibility results do not replace assistive-technology user testing or production Core Web Vitals measurements.

Reproduction: `npm ci`, `npm run check`, `npm test`, `npm run build`; start the production server on port 3123 and run `npm run test:browser`. Set `CHROME_PATH` when Chrome is installed elsewhere. Optional `CV_TEST_PDF` supplies a local extraction-only PDF fixture. Browser evidence is written to the git-ignored `audit-artifacts` directory.
